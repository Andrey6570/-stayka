# Подключение синхронизации (Firebase)

Пока в `src/firebase-config.js` пусто, Стайка работает только на одном телефоне. Чтобы друзья видели общие обеды, голосования и события, один раз настройте проект Firebase (бесплатный тариф Spark подходит).

## Шаги (около 10 минут)

1. https://console.firebase.google.com → **Добавить проект** (название, например, `stayka`; Google Analytics можно выключить).
2. **Authentication → Начать → Sign-in method → Анонимный → Включить.**
3. **Firestore Database → Создать базу данных → Производственный режим.**
   **Регион выберите в ЕС** (например `eur3 (europe)` или `europe-west`): его нельзя поменять потом, и он важен для GDPR. Впишите его в политику конфиденциальности (раздел «Третьи лица»).
4. **Firestore → Правила:** вставьте содержимое файла `firestore.rules` из репозитория и нажмите **Опубликовать**.
5. **Настройки проекта (шестерёнка) → Ваши приложения → Веб (`</>`)** → зарегистрируйте приложение, скопируйте объект `firebaseConfig`.
6. Вставьте значения `apiKey`, `authDomain`, `projectId`, `appId` в `src/firebase-config.js` и сделайте commit в `main`. GitHub Actions соберёт новый APK.

Ключи в `firebase-config.js` не секретные: защиту даёт `firestore.rules` и анонимный вход. Для порядка в **Google Cloud Console → API и сервисы → Учётные данные** можно ограничить ключ API по API (Identity Toolkit, Cloud Firestore).

## Как это устроено

- Каждый телефон входит анонимно, получая свой `uid`. Если очистить данные приложения, `uid` потеряется, и телефон выпадет из компаний (вступить можно снова по коду).
- Компания: документ `groups/{КОД}`, где КОД из 8 символов служит и секретным приглашением. Список компаний прочитать нельзя, перебрать коды практически нереально (32^8).
- Участники: `groups/{КОД}/members/{uid}` (имя и фото 128 px). Вступление = создать свой документ участника, если компания существует.
- Общее состояние: `groups/{КОД}/state/lunch`, `state/poll`, события в `events/{id}`. Читать и писать могут только участники.
- Ответы хранятся по `uid` (`resp.<uid>`, `votes.<uid>`, `rsvp.<uid>`), поэтому два человека не затирают друг другу ответы. Без связи записи ждут в кэше и отправляются потом.
- «Выйти из компании» и «Удалить все мои данные» стирают ваши ответы и профиль на сервере и удаляют анонимный аккаунт.

## Проверка правил

Файл `firestore.rules` проверен на эмуляторе Firebase (23 проверки: посторонний не читает и не пишет, участник может, нельзя вписать другого человека, нельзя подделать владельца и т.д.). Запустить эмулятор: `npx firebase-tools emulators:start --only firestore,auth` (нужна Java).

## Что ещё не сделано

- Push-уведомления (нужен FCM и Cloud Functions, это следующий этап).
- Удаление пустых компаний (когда вышли все участники, документ компании остаётся; можно очищать функцией или правилом TTL).
- Участников нельзя исключить из компании; владелец сейчас такой же участник, как остальные.
