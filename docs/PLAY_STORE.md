# Публикация в Google Play

Всё, что можно подготовить в репозитории, готово. Остаётся то, что делается только в вашем аккаунте Google Play Console. Ниже по порядку.

## 1. Что уже готово

| Что | Где |
|---|---|
| Сборка подписанного `.aab` | Actions → **Android release bundle (Google Play)** → Run workflow (нужны секреты, п. 2) |
| `targetSdk 36`, `minSdk 24`, один permission `INTERNET` | `android/variables.gradle`, манифест |
| `versionCode` растёт сам (номер запуска), `versionName 0.1.N` | `android/app/build.gradle` |
| Иконка 512×512, значок приложения | `store/icon-512.png`, `android/app/src/main/res` |
| Графика к странице: 6 скриншотов 1080×2160 и баннер 1024×500 на ru / en / el | `store/ru`, `store/en`, `store/el` |
| Политика конфиденциальности как веб-страница (ru, en, el) и инструкция по удалению данных | `public/privacy.html` → https://andrey6570.github.io/-stayka/privacy.html (после включения GitHub Pages) |
| Удаление данных в приложении | Профиль → «Отозвать согласие и удалить все мои данные», «Выйти из компании» |

## 2. Ключ загрузки (один раз)

Тестовый ключ `stayka.jks` лежит в репозитории только для установки APK, для магазина он не годится. Нужен отдельный ключ загрузки, который не попадёт в репозиторий.

1. На своём компьютере (нужна Java):
   ```
   keytool -genkeypair -v -keystore upload.jks -alias stayka-upload -keyalg RSA -keysize 2048 -validity 10000
   ```
   Пароль ключа и хранилища задайте **одинаковым**. Файл и пароль сохраните в надёжном месте (менеджер паролей, резервная копия): без него обновить приложение будет сложно.
2. Превратите файл в строку: `base64 -w0 upload.jks` (на Mac: `base64 -i upload.jks`).
3. GitHub → репозиторий Стайки → Settings → Secrets and variables → Actions → два секрета:
   - `UPLOAD_KEYSTORE_BASE64`: строка из шага 2;
   - `UPLOAD_KEYSTORE_PASSWORD`: пароль.
4. Actions → «Android release bundle (Google Play)» → Run workflow. Готовый файл появится в артефакте **stayka-aab**.

## 3. Перед публикацией обязательно

- [ ] **Firebase.** Вписать конфиг в `src/firebase-config.js` (см. `docs/FIREBASE.md`). Без него синхронизации нет, и приложение для компании друзей почти бесполезно. Регион Firestore выберите в ЕС.
- [ ] **Политика.** В `public/privacy.html` и в приложении (раздел «Политика конфиденциальности» в `src/main.js`) заполнить жёлтые места: оператор, адрес, e-mail, регион хранения. Показать юристу.
- [ ] **GitHub Pages:** Settings → Pages → Source: GitHub Actions, запустить workflow «Web app (GitHub Pages)». Адрес политики пойдёт в Play Console.
- [ ] **Аккаунт разработчика.** Если он личный и создан после ноября 2023, Google требует закрытое тестирование: не менее 12 тестировщиков не менее 14 дней подряд, только потом доступна публикация в «Производство». Для организации этого нет.
- [ ] Проверить греческие тексты у носителя языка.

## 4. Play Console: создание приложения

Все поля ниже можно копировать.

**Приложение:** название «Стайка», язык по умолчанию русский, тип «Приложение», бесплатное.
**Пакет:** `com.andrey6570.stayka`. **App signing:** включить Play App Signing (по умолчанию) и загрузить `.aab` с ключом загрузки.

## 5. Анкеты Play Console

### Целевая аудитория
Выберите **16–17 и 18+**. Не отмечайте группы младше 16: тогда не применяются правила для детских приложений. В приложении при первом запуске уже есть подтверждение «мне 16 или больше».

### Рейтинг контента (IARC, анкета)
Категория: **социальное / общение**. Ответы по сути:
- Насилие, кровь, страх: нет.
- Сексуальный контент, нагота: нет; есть провокационные личные вопросы и шутки в разделах 18+ (если анкета спрашивает про «намёки», отвечайте «да, мягкие»).
- Ненормативная лексика: нет.
- Азартные игры на деньги: нет (в словах «Объясняйки» есть «казино», «покер» как слова, играть на деньги нельзя).
- **Алкоголь, табак, наркотики: «упоминание/изображение употребления алкоголя» да**: игры с алкоголем. Раздел 18+ закрыт, есть режим «Без алкоголя».
- Взаимодействие пользователей: **да** (имена, фото и ответы видны участникам компании). Обмен местоположением: **нет** (только ссылки на место, указанные самим человеком, геолокация телефона не запрашивается).
- Покупки внутри приложения, реклама: нет.
Ожидаемый рейтинг: около 12+/16+ в зависимости от региона (ESRB Teen / PEGI 12–16), финальный выставляет IARC.

### Безопасность данных (Data safety)
Приложение собирает данные и **передаёт** их только в Firebase (Google как обработчик) и членам вашей компании.

| Тип данных | Собирается | Для чего | Передаётся третьим лицам | Обязательно |
|---|---|---|---|---|
| Имя (как называть) | Да | Функции приложения | Нет (обработчик Google не считается передачей) | Нет |
| Фото профиля | Да | Функции приложения | Нет | Нет |
| Идентификатор пользователя (анонимный uid) | Да | Функции приложения, учётная запись | Нет | Да |
| Ответы, голоса, события, названия мест (пользовательский контент) | Да | Функции приложения | Нет | Нет |
| Геолокация, контакты, платёжные данные, реклама, аналитика | **Нет** | | | |

- Шифрование при передаче: **да** (HTTPS).
- Можно ли удалить данные: **да**. В приложении «Профиль → Отозвать согласие и удалить все мои данные»; веб-адрес с инструкцией: https://andrey6570.github.io/-stayka/privacy.html#delete-ru
- Приложение следует политике семьи: **нет**, детей в целевой аудитории нет.

### Остальное
- **Реклама:** нет. **Приложение для новостей/здоровья/финансов/государства:** нет.
- **Доступ к приложению:** вход без пароля, особых данных для рецензента не нужно. В заметках можно указать: «Для проверки нажмите «Продолжить» на первом экране, затем «＋» → создать компанию или откройте демо-компанию».
- **Функции приложения «Пользовательский контент»:** имена и фото видны только участникам компании. Google может спросить про жалобы и блокировку: сейчас в приложении нет кнопки «пожаловаться» (компании закрытые, вход по секретному коду); при необходимости добавим.

## 6. Заливка и релиз

1. Play Console → «Тестирование» → «Закрытое тестирование» → создать трек, загрузить `stayka-*.aab`, добавить список тестировщиков (e-mail Google-аккаунтов).
2. Через 14 дней (если требуется) → «Производство» → подать на проверку.
3. Для следующих версий: просто запускайте workflow заново, `versionCode` вырастет сам.

## Риски проверки

- **Алкоголь.** Игры с алкоголем разрешены, если нет продажи и призывов к злоупотреблению. Раздел закрыт возрастным подтверждением, а правила напоминают пить в меру, и есть «Без алкоголя». Если Google попросит, раздел можно скрыть для Play-версии.
- **Пользовательский контент.** Если ревью потребует механизм жалоб, добавим «Пожаловаться на участника» и «Убрать из компании».
- **Политика.** С незаполненным оператором и e-mail приложение отклонят.
